# 核心商業邏輯模組

## 代收 (Deposit)

商戶發起收款請求 → 系統分配銀行帳號 → 等待客戶轉帳 → 撮合訂單

### 流程說明

1. 商戶發起代收請求
2. 系統根據可用帳號分配銀行帳號給商戶
3. 商戶將帳號提供給客戶進行轉帳
4. 系統透過銀行帳號監控偵測轉帳
5. 系統撮合轉帳資料與代收訂單

## 代付 (Withdraw)

商戶發起付款請求 → 管理員審核 → 扣款 → 第三方金流代付

### 流程說明

1. 商戶發起代付請求
2. 管理員審核該筆請求
3. 審核通過後，系統扣減商戶餘額
4. 透過第三方支付通道進行代付

## 銀行帳號管理

BankAccount + BankAccountGroup + 帳號監控整合

- 管理系統持有的銀行帳號
- 將帳號分組以支援不同商戶
- 即時監控帳號異動以偵測轉帳

## 撮合系統

當收到銀行帳號的轉帳通知時，系統需判斷該筆轉帳屬於哪筆代收訂單。

| 策略 | 說明 |
|------|------|
| UTR 精確匹配 | 以轉帳參考號（UTR）與代收訂單配對 |
| 姓名+金額匹配 | 依轉帳人姓名＋金額容差進行匹配 |
| 唯一金額匹配 | 當某金額只有一筆待撮合訂單時直接匹配 |

## 代理佣金

三層級佣金鏈：Merchant → Agent → Super_Agent

- 商戶屬於某個 Agent
- Agent 屬於某個 Super_Agent
- 每筆交易根據費率計算各層級佣金

## 費率引擎

FeeGroup + FeeRule，支援 Percentage/Fixed 計費

- FeeGroup：費率群組
- FeeRule：具體費率規則（百分比或固定金額）

## Channel 整合

多支付通道適配器，支援以下通道：

- PayPay
- HK21Pay
- VanPay
- ColaPay
- 其他通道...

每個通道有自己的 API 規格與回調格式，系統需統一抽象處理。

## 風控

Blacklist 黑名單過濾

- 依身份證、銀行帳號、手機號等欄位過濾名單
- 命中黑名單的請求直接拒絕
